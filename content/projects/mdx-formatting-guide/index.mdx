## Overview

Your portfolio supports rich MDX content with custom React components, syntax highlighting, interactive media, and more. All components are theme-aware and fully responsive.

## Typography & Text Formatting

### Basic Text Styling

You can use **bold text** for emphasis, *italic text* for subtlety, and ***bold italic*** for both. Use `inline code` for technical terms, file names, or short code snippets like `npm install` or `GPIO`.

### Headings Hierarchy

Headings automatically generate IDs and appear in the table of contents:
- **H1** (`#`) - Project title only (one per page)
- **H2** (`##`) - Main sections (shown in TOC, includes bottom border)
- **H3** (`###`) - Subsections (shown in TOC, indented)

All headings include automatic scroll margin for better anchor navigation.

#### This is an H4 Heading

H4 headings and below don't appear in the table of contents but are still useful for organizing content within sections.

##### This is an H5 Heading

Even smaller headings are available when you need fine-grained organization.

###### This is an H6 Heading

The smallest heading level, rarely needed but available.

### Links

Links are automatically enhanced with external link indicators. Here's an [internal link](#media-images-videos-3d) and an [external link](https://github.com).

External links automatically:
- Open in a new tab
- Include `rel="noopener noreferrer"`
- Show an external link icon

### Inline Code & Technical Terms

Use inline code for: `variables`, `function_names()`, `file.txt`, or technical identifiers like `Wi-Fi`, `I2C`, `PWM`, and `HTTP`.

The inline code styling is distinct from regular text with a subtle background and border.

- Second item with more content
  - Nested item level 1
  - Another nested item
    - Deeply nested item
- Back to top level
- List items have improved spacing

### Ordered Lists

1. First sequential item
2. Second sequential item
   1. Nested numbered item A
   2. Nested numbered item B
      1. Deeply nested item i
      2. Deeply nested item ii
   3. Back to second level

You can also mix ordered and unordered lists:

   - Another bullet point
     - Even deeper nesting
2. Second ordered item
   - Mix and match as needed
3. Lists maintain proper indentation

### 3D Models

Interactive 3D models can be embedded using the ModelViewer component. Models support orbit controls, zoom, and pan.

:::info
**3D Model Viewer Syntax**

The ModelViewer component supports GLB and GLTF model formats:

```mdx
<ModelViewer modelUrl="/models/your-model.glb" />
```

**Features:**
- Interactive orbit controls (click and drag to rotate)
- Mouse wheel to zoom in/out
- Theme-aware lighting
- Optimized loading with suspense
- Supports GLB and GLTF formats

**Note:** Due to React 19 compatibility limitations with Three.js libraries, the 3D model viewer is currently available for React 18 projects. For React 19 projects, consider using embedded images or videos of your 3D models until library compatibility is updated.

### Python Example

```python
def calculate_efficiency(power_in, power_out):
    """Calculate system efficiency as a percentage."""
    if power_in == 0:
        return 0
    return (power_out / power_in) * 100

# Example usage
efficiency = calculate_efficiency(1000, 850)
print(f"System efficiency: {efficiency}%")
```

## Callouts & Alerts

Callouts are custom components for highlighting important information. Five types are available:

:::info
**Information callouts** use blue styling with an info icon. Perfect for general information, tips about the system, or contextual details.
:::

:::tip
**Tips and recommendations** use purple styling with a lightbulb icon. Great for best practices, helpful hints, or insider knowledge.
:::

:::warning
**Warnings** use yellow/amber styling with a triangle icon. Use for potential issues, things to watch out for, or important considerations.
:::

:::danger
**Danger/Error alerts** use red styling with an alert icon. Reserve for critical warnings, errors, or things that could cause failures.
:::

:::success
**Success messages** use green styling with a checkmark icon. Ideal for showcasing achievements, test results, or positive outcomes.
:::

### Callout Syntax

```mdx
:::type
Your content here. Can include **markdown** formatting.
:::

Available types: info, tip, warning, danger, success
```

### Metrics Syntax

```mdx
<MetricsGrid columns={2}>
  <Metric 
    label="Label Text" 
    value="Value" 
    description="Optional description"
  />
</MetricsGrid>

columns: 2, 3, or 4 (default: 2)
```

**Note:** When using `<` or `>` symbols in attribute values, escape them as `&lt;` and `&gt;` to avoid JSX parsing errors.

Example:
```mdx
<Metric label="Response Time" value="&lt;100ms" />
```

## Best Practices

:::tip
**Content Writing Guidelines**
- Start with H1 for the project title (one per page)
- Use H2 for major sections
- Use H3 for subsections
- Don't skip heading levels
- Add descriptive alt text to all images
- Use callouts to highlight important information
- Include code comments for clarity
- Provide context before showing code examples
:::

### Recommended Project Structure

A typical project documentation should follow this structure:

1. **Introduction** (H1) - Project title and brief overview
2. **Project Overview** (H2) - Goals, context, and motivation
3. **Technical Details** (H2) - Implementation specifics
   - Hardware/Software Components (H3)
   - Design Decisions (H3)
4. **Results & Outcomes** (H2) - Metrics, achievements, learnings
5. **Future Work** (H2) - Potential improvements and next steps

### Combining Components

Callouts work great with code blocks for tutorials:

:::info
**Example: Sensor Calibration**

Here's how to implement calibration for analog sensors:

```python
def calibrate_sensor(raw_value, offset=2.5, scale=0.98):
    """Apply calibration to raw sensor reading."""
    calibrated = raw_value * scale + offset
    return calibrated

# Usage
reading = calibrate_sensor(analog_read(pin))
```

:::success
This calibration achieved ±0.1% accuracy across the full measurement range!
